# TechZone Motors — UI-система и порядок внедрения для нейросети

## Назначение документа

Документ описывает целевую UI-систему для сайта TechZone Motors: светлый e-commerce / showroom-интерфейс для продажи питбайков, эндуро и другой мототехники с упором на лидогенерацию.

Цель внедрения — уйти от ощущения шаблонного маркетплейса и собрать единый, чистый, доверительный интерфейс: светлый фон, крупная типографика, понятные CTA, аккуратные карточки, предсказуемая навигация, стабильные состояния компонентов и хорошая мобильная версия.

Документ предназначен для передачи нейросети или Cursor как техническо-дизайнерское задание.

---

## 0. Главные принципы интерфейса

1. Интерфейс должен быть светлым, современным и уверенным.
2. Сайт должен выглядеть как аккуратный магазин / showroom техники, а не как темный маркетплейс.
3. Основная цель сайта — лиды: заявка, подбор техники, звонок.
4. CTA должны быть заметными, но не агрессивными.
5. Визуальная система должна быть единой на всех страницах.
6. Медиа-контент может быть разным: фото на прозрачном фоне, фото на белом фоне, AI-фоны. UI должен органично принимать разные типы изображений.
7. Не использовать кислотный оранжевый и тяжелый черный как основу.
8. Все интерактивные элементы должны иметь состояния: default, hover, active, focus, disabled.
9. Все основные кликабельные зоны должны быть удобны на мобильных устройствах.
10. Бизнес-логика, маршруты, данные и текущие сценарии сайта не должны ломаться.

# 1. UI-элементы / контролы

## 1.1. Кнопки

### Типы кнопок

Использовать три варианта:

1. **Primary button**
   - Основная кнопка действия.
   - Используется для лидогенерации.
   - Примеры текста: `Оставить заявку`, `Подобрать технику`, `Получить консультацию`.

2. **Secondary button**
   - Вторичное действие.
   - Используется для переходов без прямого лида.
   - Примеры текста: `Смотреть каталог`, `Подробнее`, `Сравнить модели`.

3. **Ghost / text button**
   - Тихое действие.
   - Используется внутри карточек, модалок, футера, вторичных блоков.

### Визуальные параметры

```css
--btn-height-md: 48px;
--btn-height-lg: 56px;
--btn-padding-x-md: 20px;
--btn-padding-x-lg: 28px;
--btn-radius: 14px;
--btn-font-size: 15px;
--btn-font-weight: 600;
```

Primary:

```css
--btn-primary-bg: #2B6EF2;
--btn-primary-bg-hover: #245FDB;
--btn-primary-bg-active: #1F51BE;
--btn-primary-text: #FFFFFF;
```

Secondary:

```css
--btn-secondary-bg: #FFFFFF;
--btn-secondary-bg-hover: #F3F6FB;
--btn-secondary-border: #D7DFEA;
--btn-secondary-text: #1E293B;
```

Ghost:

```css
--btn-ghost-bg: transparent;
--btn-ghost-bg-hover: #EEF3FA;
--btn-ghost-text: #334155;
```

### Где внедрять

- Header: primary CTA справа.
- Hero: primary + secondary.
- Карточка товара: primary `Оставить заявку`, secondary/ghost `Подробнее`.
- Модалка заявки: primary на отправку формы.
- Мобильная версия: primary CTA во всю ширину, если это основной сценарий.

### Правила

- Не ставить две одинаково сильные кнопки рядом.
- На одном смысловом блоке должен быть один главный CTA.
- Не использовать `Купить`, если фактическая цель — заявка/звонок.
- Все кнопки должны иметь keyboard focus.
- Минимальная кликабельная область: 44×44 px.

---

## 1.2. Поля ввода

### Назначение

Используются в формах заявки, обратного звонка, подбора техники, фильтрах каталога.

### Визуальные параметры

```css
--input-height: 48px;
--input-radius: 12px;
--input-padding-x: 14px;
--input-bg: #FFFFFF;
--input-border: #D6DEE8;
--input-border-hover: #B8C4D4;
--input-border-focus: #2B6EF2;
--input-text: #1E293B;
--input-placeholder: #94A3B8;
--input-error: #D32F2F;
```

### Состояния

- Default: белый фон, светлый border.
- Hover: border чуть темнее.
- Focus: акцентный outline или border.
- Error: красный border + текст ошибки под полем.
- Disabled: серый фон, сниженный контраст.

### Где внедрять

- Форма заявки в модалке.
- Форма подбора техники.
- Поле телефона.
- Поле имени.
- Комментарий/сообщение.
- Поиск по каталогу, если используется.

### Правила

- Label всегда должен быть видимым, не только placeholder.
- Ошибка должна быть текстом, а не только красной рамкой.
- Телефон должен иметь удобную маску ввода.
- Поля в мобильной версии должны быть не ниже 48 px.

---

## 1.3. Чекбоксы, радиокнопки, переключатели

### Чекбоксы

Использовать для множественного выбора:
- категории техники;
- наличие;
- параметры;
- согласие на обработку данных.

```css
--checkbox-size: 20px;
--checkbox-radius: 6px;
--checkbox-border: #CBD5E1;
--checkbox-checked-bg: #2B6EF2;
```

### Радиокнопки

Использовать для выбора одного варианта:
- тип техники;
- уровень опыта;
- возраст/рост ребенка;
- способ связи.

```css
--radio-size: 20px;
--radio-border: #CBD5E1;
--radio-checked: #2B6EF2;
```

### Switch / toggle

Использовать только для бинарных настроек, не для фильтров каталога.

Пример:
- `Показывать только в наличии` — можно как switch.
- `Питбайки / Эндуро` — нельзя как switch, лучше tabs или chips.

## 1.4. Выпадающие списки

### Где использовать

- сортировка каталога;
- выбор категории;
- выбор города/способа связи;
- фильтр по объему двигателя, цене, росту.

### Визуальные параметры

```css
--select-height: 44px;
--select-radius: 12px;
--select-bg: #FFFFFF;
--select-border: #D6DEE8;
--select-text: #1E293B;
```

### Правила

- На мобильном длинные select лучше превращать в bottom sheet / drawer.
- Сортировка должна быть отдельным компактным контролом над каталогом.
- Не перегружать первый экран фильтрами.

# 2. Навигационные компоненты

## 2.1. Header

### Цель

Header должен быть чистой светлой панелью, которая не спорит с контентом и всегда дает быстрый доступ к каталогу, телефону и заявке.

### Desktop-структура

Слева:
- логотип TechZone Motors.

Центр:
- Каталог
- Питбайки
- Эндуро
- Квадроциклы / другая категория, если есть
- Доставка / Оплата
- Контакты

Справа:
- телефон;
- primary CTA `Подобрать технику` или `Оставить заявку`.

### Визуальные параметры

```css
--header-height: 72px;
--header-bg: rgba(255,255,255,0.88);
--header-border: #E2E8F0;
--header-blur: 16px;
--header-z-index: 50;
```

### Поведение

- Header sticky.
- При скролле появляется легкая тень / border.
- На мобильной версии — логотип, телефон/иконка звонка, burger.

---

## 2.2. Меню

### Desktop

- Горизонтальное меню.
- Без сложных dropdown на первом этапе.
- Активный пункт выделяется цветом или нижней линией.

### Mobile

- Burger открывает drawer.
- В drawer: крупные пункты меню, телефон, CTA.
- Drawer должен закрываться по Esc, клику вне области и выбору пункта.

---

## 2.3. Breadcrumbs

### Где использовать

- Страница каталога.
- Категория.
- Карточка товара.
- Статьи.

### Формат

`Главная / Каталог / Питбайки / Название модели`

### Правила

- Не показывать breadcrumbs на главной.
- Последний элемент не ссылка.
- Визуально — маленький, спокойный текст.

```css
--breadcrumb-font-size: 13px;
--breadcrumb-color: #64748B;
--breadcrumb-active-color: #1E293B;
```

---

## 2.4. Вкладки

### Где использовать

На карточке товара:
- Описание
- Характеристики
- Доставка
- Гарантия / вопросы

### Правила

- На desktop — горизонтальные tabs.
- На mobile — accordion или segmented tabs, если пунктов мало.
- Активная вкладка должна быть очевидной.

---

## 2.5. Ссылки

### Правила

- Ссылки в тексте выделять цветом.
- Ссылки в меню — без подчеркивания, с hover-состоянием.
- Ссылки в footer — спокойные, но читаемые.

```css
--link-color: #2B6EF2;
--link-hover: #1F51BE;
```

# 3. Информационные компоненты

## 3.1. Иконки

### Стиль

- Единый набор outline-иконок.
- Толщина линии 1.75–2 px.
- Не смешивать разные наборы иконок.

### Размеры

```css
--icon-sm: 16px;
--icon-md: 20px;
--icon-lg: 24px;
```

### Где использовать

- преимущества в hero;
- контакты;
- карточки доверия;
- фильтры;
- статусы;
- кнопки с иконкой.

### Правила

- Декоративные иконки не должны конкурировать с текстом.
- Важные иконки должны иметь текстовую подпись.
- Не использовать иконки ради украшательства.

---

## 3.2. Подсказки / tooltips

### Где использовать

- объяснение технических характеристик;
- подсказки в форме подбора;
- пояснение условий доставки/гарантии.

### Визуальные параметры

```css
--tooltip-bg: #111827;
--tooltip-text: #FFFFFF;
--tooltip-radius: 8px;
--tooltip-padding: 8px 10px;
--tooltip-max-width: 220px;
```

### Правила

- Tooltip появляется по hover и focus.
- Не помещать в tooltip критически важную информацию.
- На мобильном лучше использовать info-popover по тапу.

---

## 3.3. Уведомления / snackbar / toast

### Где использовать

- успешная отправка заявки;
- ошибка отправки формы;
- товар добавлен в сравнение/избранное, если есть;
- системные ошибки.

### Типы

- Success
- Error
- Warning
- Info

```css
--success: #28A745;
--error: #D32F2F;
--warning: #F59E0B;
--info: #3178C6;
```

### Правила

- Toast не должен перекрывать CTA.
- На mobile располагать снизу, но выше sticky-кнопок.
- Автоскрытие 3–5 секунд.
- Ошибки формы лучше показывать рядом с полем, а не только toast.

---

## 3.4. Индикаторы прогресса

### Где использовать

- загрузка каталога;
- отправка формы;
- загрузка изображений;
- применение фильтров.

### Форматы

1. Spinner — для коротких загрузок.
2. Skeleton — для карточек каталога.
3. Linear progress — для длинных операций.

### Правила

- Для каталога предпочтительнее skeleton, а не spinner.
- Кнопка отправки формы должна показывать loading state.
- Не блокировать всю страницу без необходимости.

# 4. Контейнеры

## 4.1. Общий layout

### Основные параметры

```css
--page-bg: #F5F7FA;
--surface-bg: #FFFFFF;
--container-max: 1200px;
--container-padding-desktop: 32px;
--container-padding-tablet: 24px;
--container-padding-mobile: 16px;
--section-gap-desktop: 72px;
--section-gap-mobile: 44px;
```

### Правила

- Не растягивать контент на всю ширину без причины.
- Использовать единый max-width.
- Между секциями должен быть воздух.
- Блоки должны иметь понятную иерархию: hero → категории/подбор → каталог → доверие → статьи/FAQ → footer.

---

## 4.2. Hero-контейнер

### Назначение

Первый экран должен объяснять, что продается, почему магазину можно доверять и какое действие нужно совершить.

### Структура

- Заголовок.
- Подзаголовок.
- 1 primary CTA.
- 1 secondary CTA.
- 2–3 коротких trust-пункта.
- Изображение техники или композиционная зона.

### Визуальный стиль

```css
--hero-bg: #EEF4FF;
--hero-radius: 32px;
--hero-padding-desktop: 56px;
--hero-padding-mobile: 24px;
```

### Правила

- Не делать карусель как главный hero.
- Не перегружать первым экраном каталогом.
- Основной CTA должен быть виден без скролла.

---

## 4.3. Карточки товаров

### Назначение

Карточка должна быть не просто плиткой каталога, а чистым коммерческим блоком: изображение, название, цена, короткая польза, действие.

### Структура

1. Зона изображения.
2. Название.
3. Короткие параметры.
4. Цена.
5. CTA.
6. Вторичная ссылка `Подробнее`.

### Визуальные параметры

```css
--card-bg: #FFFFFF;
--card-radius: 24px;
--card-border: #E2E8F0;
--card-padding: 18px;
--card-shadow: 0 8px 24px rgba(15, 23, 42, 0.06);
--card-shadow-hover: 0 14px 36px rgba(15, 23, 42, 0.10);
```

### Правила для изображений

- Поддерживать изображения на прозрачном фоне.
- Поддерживать изображения на белом фоне.
- Поддерживать изображения с AI-фоном.
- Внутри карточки должна быть единая зона изображения с `object-fit: contain`.
- Не накладывать тяжелые эффекты поверх товара.
- Если используется декоративная подложка, она должна быть системной и очень мягкой.

### Пример зоны изображения

```css
.product-media {
  background: linear-gradient(180deg, #F8FAFC 0%, #EEF3F8 100%);
  border-radius: 20px;
  aspect-ratio: 4 / 3;
  display: flex;
  align-items: center;
  justify-content: center;
  overflow: hidden;
}

.product-media img {
  width: 92%;
  height: 92%;
  object-fit: contain;
}
```

---

## 4.4. Модальные окна

### Где использовать

- Заявка.
- Подбор техники.
- Быстрый просмотр товара.
- Обратный звонок.

### Визуальные параметры

```css
--modal-width: 560px;
--modal-radius: 24px;
--modal-padding: 28px;
--modal-overlay: rgba(15, 23, 42, 0.48);
```

### Правила

- Модалка должна блокировать скролл body.
- Фокус должен оставаться внутри модалки.
- Закрытие: Esc, крестик, клик по overlay.
- На mobile модалка может быть bottom sheet.

---

## 4.5. Панели доверия

### Где использовать

- Под hero.
- Перед формой заявки.
- На карточке товара.
- В footer.

### Примеры содержимого

- Помогаем подобрать под рост и опыт.
- Техника в наличии.
- Консультация перед покупкой.
- Доставка / самовывоз.
- Поддержка после покупки.

# 5. Типографика

## 5.1. Шрифты

Рекомендуемый базовый стек:

```css
--font-base: Inter, Manrope, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
```

### Правила

- Использовать один основной шрифт.
- Не смешивать много гарнитур.
- Для ощущения современного магазина лучше Manrope или Inter.
- Заголовки должны быть крупными, но не кричащими.

---

## 5.2. Размеры

```css
--fs-hero: clamp(40px, 5vw, 72px);
--lh-hero: 0.95;

--fs-h1: clamp(34px, 4vw, 56px);
--lh-h1: 1.02;

--fs-h2: clamp(28px, 3vw, 42px);
--lh-h2: 1.08;

--fs-h3: 24px;
--lh-h3: 1.18;

--fs-body-lg: 18px;
--lh-body-lg: 1.55;

--fs-body: 16px;
--lh-body: 1.55;

--fs-small: 14px;
--lh-small: 1.45;

--fs-caption: 12px;
--lh-caption: 1.35;
```

---

## 5.3. Вес

```css
--fw-regular: 400;
--fw-medium: 500;
--fw-semibold: 600;
--fw-bold: 700;
--fw-black: 800;
```

### Применение

- Hero title: 700–800.
- Заголовки секций: 700.
- Названия товаров: 600–700.
- Body: 400–500.
- Цена: 700.
- CTA: 600.

---

## 5.4. Правила типографики

- Не делать много текста в карточке товара.
- В hero максимум 1 сильный заголовок и 1 короткий подзаголовок.
- Длина строк в статьях: 680–820 px.
- Описания товара дробить на короткие блоки.
- Не использовать uppercase для длинных фраз.

# 6. Цветовая палитра

## 6.1. Базовая палитра

```css
:root {
  --color-bg: #F5F7FA;
  --color-bg-warm: #F7F3EE;
  --color-surface: #FFFFFF;
  --color-surface-soft: #F8FAFC;

  --color-text: #111827;
  --color-text-secondary: #334155;
  --color-text-muted: #64748B;
  --color-text-disabled: #94A3B8;

  --color-border: #E2E8F0;
  --color-border-strong: #CBD5E1;
}
```

---

## 6.2. Акцентная палитра

Основной вариант — доверительный синий:

```css
--color-primary: #2B6EF2;
--color-primary-hover: #245FDB;
--color-primary-active: #1F51BE;
--color-primary-soft: #EAF1FF;
```

Дополнительный теплый акцент, использовать дозированно:

```css
--color-accent-warm: #E5573B;
--color-accent-warm-hover: #CC4630;
--color-accent-warm-soft: #FFF0EC;
```

### Правила

- Не использовать кислотный оранжевый.
- Не использовать черный фон как основу.
- Синий — для основных CTA и ссылок.
- Теплый акцент — для бейджей, промо, отдельных акцентов.
- Не использовать более одного сильного акцента в одном блоке.

---

## 6.3. Семантические цвета

```css
--color-success: #28A745;
--color-success-soft: #EAF7EE;

--color-error: #D32F2F;
--color-error-soft: #FDECEC;

--color-warning: #F59E0B;
--color-warning-soft: #FFF7E6;

--color-info: #3178C6;
--color-info-soft: #EAF3FF;
```

---

## 6.4. Где применять

- Фон сайта: `--color-bg`.
- Карточки/модалки/header: `--color-surface`.
- CTA: `--color-primary`.
- Цена: `--color-text` или `--color-primary`, в зависимости от композиции.
- Ошибки формы: `--color-error`.
- Успешная заявка: `--color-success`.

# 7. Стили и графика

## 7.1. Скругления

```css
--radius-xs: 6px;
--radius-sm: 10px;
--radius-md: 14px;
--radius-lg: 20px;
--radius-xl: 24px;
--radius-2xl: 32px;
--radius-pill: 999px;
```

### Где применять

- Кнопки: 12–14 px.
- Поля: 12 px.
- Карточки: 20–24 px.
- Hero: 28–32 px.
- Модалки: 24 px.
- Chips/badges: pill.

---

## 7.2. Тени

```css
--shadow-xs: 0 1px 2px rgba(15, 23, 42, 0.04);
--shadow-sm: 0 4px 12px rgba(15, 23, 42, 0.06);
--shadow-md: 0 8px 24px rgba(15, 23, 42, 0.08);
--shadow-lg: 0 16px 40px rgba(15, 23, 42, 0.12);
```

### Правила

- Тени должны быть мягкими.
- Не использовать тяжелые черные тени.
- Hover карточки — легкий lift + усиление тени.
- Header — только тонкая тень или border.

---

## 7.3. Иконки

### Требования

- Один набор иконок.
- Outline стиль.
- Не использовать разношерстные emoji как UI-иконки.
- Цвет иконок наследуется от текста или токена.

---

## 7.4. Изображения

### Сценарии

Сайт должен поддерживать:
1. PNG/WebP на прозрачном фоне.
2. Фото на белом фоне.
3. Фото с AI-фоном.
4. Фото на едином showroom-фоне.

### Универсальный подход

- Для transparent PNG: использовать мягкую светлую подложку карточки.
- Для белого фона: отделять image-area от карточки легким фоном.
- Для AI-фона: не накладывать тяжелые эффекты, но использовать одинаковый crop/ratio.
- Для всех: `object-fit: contain`, единый aspect-ratio.

### Запрещено

- Делать изображения мелкими.
- Использовать сильный glow.
- Использовать случайные градиенты на каждой карточке.
- Искажать пропорции техники.

# 8. Анимация и взаимодействия

## 8.1. Базовые transition

```css
--transition-fast: 120ms ease-out;
--transition-base: 180ms ease-out;
--transition-slow: 260ms ease-out;
```

Применение:

```css
transition: background-color var(--transition-base),
            border-color var(--transition-base),
            box-shadow var(--transition-base),
            transform var(--transition-base),
            opacity var(--transition-base);
```

---

## 8.2. Hover

### Карточки

```css
.card:hover {
  transform: translateY(-3px);
  box-shadow: var(--shadow-md);
}
```

### Кнопки

- Primary: цвет становится чуть темнее.
- Secondary: фон слегка подсвечивается.
- Ghost: появляется мягкий фон.

### Ссылки

- Цвет темнее.
- Возможна тонкая underline-анимация.

---

## 8.3. Active / pressed

- Кнопка немного уменьшается: `scale(0.98)`.
- Не использовать сильные bounce-эффекты.

---

## 8.4. Focus

```css
:focus-visible {
  outline: 2px solid var(--color-primary);
  outline-offset: 3px;
}
```

### Правила

- Focus должен быть видимым.
- Не убирать outline без замены.
- Проверить keyboard navigation для header, modals, forms, catalog cards.

---

## 8.5. Page transitions

Использовать умеренно:

- fade-in секций;
- плавное появление карточек;
- slide для mobile drawer;
- fade для modal overlay.

Не использовать:

- сложные параллаксы;
- агрессивные анимации;
- длительные intro-анимации;
- эффекты, мешающие покупке/заявке.

---

## 8.6. Reduced motion

Обязательно добавить:

```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    scroll-behavior: auto !important;
    transition-duration: 0.01ms !important;
  }
}
```

---

# 9. Порядок внедрения без таймлайна

## Этап 1. Foundation / дизайн-токены

Сначала внедрить базовые переменные:
- цвета;
- типографика;
- spacing;
- radii;
- shadows;
- transitions;
- container widths;
- responsive breakpoints.

Что изменить:
- `globals.css`;
- `tailwind.config`, если используется Tailwind;
- общий layout;
- базовые классы поверхности, контейнера, секций.

Результат этапа:
- сайт получает светлую базу;
- исчезают старые темные/кислотные стили;
- появляется единый визуальный язык.

---

## Этап 2. Базовые контролы

Внедрить компоненты:
- Button;
- Input;
- Textarea;
- Checkbox;
- Radio;
- Select;
- Switch;
- FormField;
- ErrorMessage.

Что важно:
- не редизайнить страницы вручную до завершения базовых компонентов;
- все формы должны использовать одни и те же компоненты;
- CTA должны стать едиными по стилю.

---

## Этап 3. Навигация

Внедрить:
- новый header;
- desktop menu;
- mobile drawer;
- breadcrumbs;
- tabs для карточки товара;
- footer navigation.

Что важно:
- header не должен быть визуально тяжелым;
- CTA и телефон должны быть доступны всегда;
- mobile drawer должен быть полноценным, а не временной заглушкой.

---

## Этап 4. Контейнеры и layout страниц

Внедрить:
- единый PageContainer;
- Section;
- Surface/Card;
- HeroContainer;
- ProductGrid;
- ProductCard;
- Modal/Dialog;
- TrustPanel.

Что важно:
- сначала контейнеры, потом конкретный визуал страниц;
- не допускать случайных отступов в разных местах;
- привести все секции к общей сетке.

---

## Этап 5. Главная страница

Собрать главную в новой структуре:
1. Hero.
2. Быстрые преимущества / trust points.
3. Блок подбора техники.
4. Популярные модели / категории.
5. Почему нам доверяют.
6. FAQ / статьи.
7. Финальный CTA.

Что важно:
- не начинать главную с обычного каталога;
- hero должен продавать доверие и сценарий подбора;
- на первом экране не должно быть визуального шума.

---

## Этап 6. Каталог и карточки товаров

Внедрить:
- сетку каталога;
- карточки товаров;
- фильтры;
- сортировку;
- empty state;
- loading skeleton.

Что важно:
- карточка должна быть чистой и коммерческой;
- изображение должно занимать достаточно места;
- CTA должен быть очевидным;
- фильтры не должны душить интерфейс.

---

## Этап 7. Карточка товара / модалка товара

Внедрить:
- крупную product media zone;
- блок цены и CTA;
- характеристики;
- tabs/accordion;
- форму заявки;
- trust-блок рядом с CTA.

Что важно:
- главный сценарий — не покупка через корзину, а заявка/консультация;
- CTA должен быть рядом с ценой и ключевыми параметрами;
- характеристики должны быть читаемыми, не простыней.

---

## Этап 8. Информационные компоненты и состояния

Внедрить:
- toast/snackbar;
- tooltips;
- icons;
- progress/spinner;
- skeleton;
- success/error states;
- empty states.

Что важно:
- после отправки заявки пользователь должен понимать результат;
- ошибки формы должны быть понятными;
- загрузка каталога не должна выглядеть как поломка.

---

## Этап 9. Анимации и интерактив

Внедрить:
- hover карточек;
- hover/focus кнопок;
- modal transitions;
- drawer transitions;
- reduced-motion;
- smooth scroll для якорей, если используется.

Что важно:
- анимации должны быть быстрыми и утилитарными;
- не добавлять motion ради красоты;
- все transitions должны использовать токены.

---

## Этап 10. Мобильная адаптация

Проверить и доработать:
- header;
- mobile drawer;
- hero;
- карточки каталога;
- фильтры;
- формы;
- модалки;
- footer.

Что важно:
- никаких горизонтальных скроллов;
- CTA в карточке — на всю ширину;
- формы удобны большим пальцем;
- телефон и заявка доступны быстро.

---

## Этап 11. QA и финальная полировка

Проверить:
- контраст;
- focus states;
- hover states;
- mobile layout;
- формы;
- модалки;
- пустые состояния;
- загрузочные состояния;
- единые отступы;
- единые радиусы;
- отсутствие старых цветов и стилей.

Финальный критерий:
сайт должен ощущаться как единая светлая дизайн-система, а не набор отдельных правок.

Перед завершением каждой итерации проверить:

1. Сборка проходит без ошибок.
2. Нет горизонтального скролла на mobile.

4. CTA ведут в нужные сценарии.
5. Формы отправляются как раньше.

11. Изображения не искажаются.
12. Toast/error/success состояния работают.
13. На mobile основные действия доступны без мелких попаданий.
